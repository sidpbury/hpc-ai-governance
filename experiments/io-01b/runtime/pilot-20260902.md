# IO-01B Phase 2 pilot — 2026-09-02

This pilot is retained for reproducibility but excluded from the evidence-fed
AI comparison because the PSI sampler failed before recording data.

## Configuration

- Source commit: `27c184ba8503a2170edee7271b23a4718844ffe1`
- Partition: `tier3`
- Account: `rc-help`
- Dataset: 12,000 deterministic files on shared Ceph scratch
- Logical bytes/pass: 30,045,829
- Measurement request: 1 CPU, 20 GiB memory, 20 minutes
- Measurement jobs: 5 sequential jobs
- Scans/job: 3

## Valid measurements

All five jobs completed with exit code 0 and all five workload checksum tests
reported `PASS`.

Observed scan elapsed times were approximately 0.974, 0.975, 0.978, 1.474,
and 1.971 seconds. `/usr/bin/time -v` peak RSS was approximately 21.4--23.3
MiB, demonstrating that the deliberately generous 20 GiB request is far above
actual process memory demand.

Runs 2 and 3 were slower and also showed dramatically more voluntary and
involuntary context switches than runs 1, 4, and 5. This is precisely the type
of run-to-run variation for which valid CPU/memory/I/O PSI evidence is useful.

## Instrumentation failure

Every PSI monitor exited with a `ValueError` because the SPORC kernel returned
CPU `full` fields (`cpu_full_avg10`, `cpu_full_avg60`, `cpu_full_avg300`, and
`cpu_full_total`) that were absent from the initial CSV field list. The
resulting `psi.csv` files contain only headers.

The first broad `sacct` query also requested unsupported `DiskRead` and
`DiskWrite` fields. The collector's fallback successfully captured core Slurm
accounting, but the site-specific query is corrected in the next revision.

## Disposition

Do not provide this pilot evidence packet to the baseline or Markdown AI
conditions. Rerun the researcher-controlled Phase 2 measurement after the PSI
and `sacct` fixes, then freeze that corrected evidence packet for the A/B test.
